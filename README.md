# Остаток — Telegram Mini App

Учёт расходов с накопительным дневным бюджетом.

```
Telegram Mini App  →  Supabase Edge Function  →  Supabase Database
```

Клиент не обращается к таблицам напрямую. RLS включён, политик нет — значит
publishable-ключ не даёт доступа ни к одной строке. Все данные идут через
Edge Function, которая работает с БД под service role только после проверки
подписи Telegram `initData`.

## Логика расчёта

```
свободный доход = доход − обязательные расходы − накопления
бюджет на день  = свободный доход / число дней в периоде
остаток сегодня = остаток вчера + бюджет на день − траты за сегодня
```

Остаток не обнуляется: копится, если тратить меньше нормы, и уходит в минус,
если больше. Период задаётся произвольно, к календарному месяцу не привязан.

## Структура

```
public/                        ← только эту папку загружаем на хостинг
├── index.html                 разметка и стили
└── js/
    ├── config.js              публичные адрес проекта и ключ
    ├── tg.js                  Telegram WebApp SDK, BackButton
    ├── api.js                 клиент Edge Function
    └── app.js                 логика экранов и расчёта
supabase/functions/api/        разворачивается в Supabase, на хостинг не идёт
├── index.ts                   маршруты
├── telegram.ts                проверка подписи initData
├── validate.ts                валидация входных данных
└── deno.json
.env.example                   какие секреты нужны и куда их класть
```

## Авторизация

`Telegram.WebApp.initData` уходит в заголовке `X-Telegram-Init-Data`.
Edge Function пересчитывает HMAC-SHA256 по Bot Token и сравнивает с `hash`;
только после совпадения Telegram user id считается настоящим.
`initDataUnsafe` для авторизации не используется, `user_id` из тела запроса
не принимается ни в одном маршруте.

## Маршруты Edge Function

Все — `POST`, база `https://<project>.supabase.co/functions/v1/api`.

| Маршрут                | Назначение                                        |
|------------------------|---------------------------------------------------|
| `/init`                | пользователь (создаётся при первом входе) + активный период |
| `/period/current`      | текущий финансовый период                          |
| `/period/create`       | период после онбординга; при пересечении дат обновляет существующий |
| `/period/get`          | период вместе с транзакциями                       |
| `/period/list`         | все периоды с суммой трат — для экрана «История»    |
| `/transaction/create`  | создание транзакции                                |
| `/transaction/list`    | транзакции периода                                 |
| `/transaction/update`  | редактирование транзакции                          |
| `/transaction/delete`  | удаление транзакции                                |

`daily_budget` считает сервер — клиент не может записать произвольное значение.

## Секреты

Единственный секрет — `TELEGRAM_BOT_TOKEN`, он задаётся в
Supabase Dashboard → Project Settings → Edge Functions → Secrets.
`SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` подставляются в функцию
автоматически. Service role key во frontend не попадает никогда.

## Разработка

Локально `public/index.html` открывается, но данные не загрузятся: без Telegram нет
`initData`, и приложение покажет приветственный экран с подсказкой. Проверять
нужно внутри Telegram по HTTPS-адресу.
